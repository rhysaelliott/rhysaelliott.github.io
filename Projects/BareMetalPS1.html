Bare-Metal PS1

  • C
  • PS1
  • MIPS

This project focussed on creating OBB Collision on the PS1 without the use of a library in C. The goal of the project was to effectively port a physics and collision project I had completed in my second year of uni. The previous project can be found here.

PS1 Programming

There are multiple ways to program the PS1, most involve using SDKs (either created by Sony or open-source) but for this project I wanted to take a bare-metal approach. This involved using a GCC toolchain that targets the MIPS architecture. To begin with, I replicated the examples on spicyjpeg's ps1-bare-metal github repo. This taught me how to render a cube, make use of textures and capture controller input amongst other things.

In systems like the PS1, components like the GPU aren't controlled through commands but through writing bit patterns into special memory mapped registers. This approach means that the GPU can read instructions from RAM without the CPU needing to feed it which accelerates graphic performance. Adjusting to this was one of the greatest difficulties in porting.

The system does not feature a floating point computation unit. As such, any math that requires fractional precision, such as rendering or physics calculations, must use fixed-point math instead. To make this easier I made various helper macros. The format used for fixed-point math uses 12 bits for fractional values to follow the format of the GTE (mentioned later).

Examples and their uses can be seen below:

	
typedef int64_t fixed_point_t;
#define FIXED_POINT_FRACTIONAL_BITS 12
#define ONE (1<<12)
#define FP_MUL(a, b) (((a) * (b)) >> FIXED_POINT_FRACTIONAL_BITS)
#define FP_DIV(a, b) (((a) << FIXED_POINT_FRACTIONAL_BITS) / (b))
Projection ProjectOntoAxis(OBBCollider* obb, Vector3 axis)
{
    Vector3 halfExtents;
    halfExtents.x = FP_DIV((obb->_maxCorner.x - obb->_minCorner.x), 2 * ONE);
    halfExtents.y = FP_DIV((obb->_maxCorner.y - obb->_minCorner.y), 2 * ONE);
    halfExtents.z = FP_DIV((obb->_maxCorner.z - obb->_minCorner.z), 2 * ONE);

    Vector3 centre;
    centre.x = FP_DIV((obb->_minCorner.x + obb->_maxCorner.x), 2 * ONE);
    centre.y = FP_DIV((obb->_minCorner.y + obb->_maxCorner.y), 2 * ONE);
    centre.z = FP_DIV((obb->_minCorner.z + obb->_maxCorner.z), 2 * ONE);

    GTEMatrix rotMatrix = obb->_transform->rotationMatrix;

    Vector3 normal = axis;

    
    Vector3 worldCentre = Vec3Transform(centre,obb->_transform->position);
    worldCentre.x*=ONE;
    worldCentre.y*=ONE;
    worldCentre.z *=ONE;
    Vector3 localVertices[8];
    int index = 0;
    for(int x = -ONE; x<=ONE; x+=2*ONE){
        for(int y=-ONE;y<=ONE;y+=2*ONE){
            for(int z =-ONE;z<=ONE;z+=2*ONE){

                localVertices[index] = (Vector3){FP_MUL(x,halfExtents.x), FP_MUL(y,halfExtents.y), FP_MUL(z,halfExtents.z)};
                index++;
            }
        }
    }

    for(int i = 0; i<8;i++)
    {
        localVertices[i] = Vec3TransformNormal(localVertices[i], rotMatrix);
    }

    normal = Vec3Normalise(normal);

    fixed_point_t minProj = INT64_MAX;
    fixed_point_t maxProj = -INT64_MAX;

    for(int i=0; i<8;i++)
    {
        Vector3 vertex = localVertices[i];
        fixed_point_t proj = Vec3DotProduct(vertex, normal);
        minProj = min(minProj, proj);
        maxProj = max(maxProj, proj);
    }

    fixed_point_t projectedCentre = -Vec3DotProduct(worldCentre, normal);
    fixed_point_t min = (projectedCentre + minProj);
    fixed_point_t max = (projectedCentre + maxProj); 
    printf("keep: %d\n", projectedCentre);
    printf("%d", min);
    printf("%d", max);
    printf("%d", minProj);
    printf("%d", maxProj);

    Projection result;
    result.max = max;
    result.min = min;
    return result;
}

The PS1 does not support textures larger than 256x256, additionally these textures must be 4-bit or 8-bit. In order to replicate the look of my old project I had to convert the textures used then to fit these restraints. Unlike modern APIs, the PS1 GPU consumes a linked list of commands constructed each frame. I had to manually form each packet (quad, sprite, texture block) and link them through the Ordering Table so the GPU could render them front-to-back.

The PS1 has a special coprocessor for 3D graphics calculations known as the Geometry Transformation Unit (GTE) which is not memory-mapped but accessed through inline assembly instructions. I used the GTE for both rendering and some physics math.

Physics & Collision

The physics and collision in my project is entirely based on my 2nd year university project. This includes basic acceleration-based force accumulation, friction, drag and OBB collision detection (using SAT) and resolution. The major challenge here was implementing fixed-point math and also making use of the GTE in place of the SIMD used in DirectXMath.
